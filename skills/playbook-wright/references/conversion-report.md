# 转换报告

报告跟随业务产物存放。内容可以短，但需足以判断语义与可运行性。

## 来源与运行目标

记录转换方向、原文件/完整测试标题或流程 ID、可获取的版本、输出清单/脚本/Profile/TC、schemaVersion、Skill 与 SDK 版本、使用的 Playwright project/config、数据类别、角色与副作用。涉及编排时记录 Book/Section 与脚本对应关系。Skill 安装页当前为 0.7.1，适配客户端 v0.4，schemaVersion 仍为 1；不将它们当成 SDK 包版本。新增或移除打码/语音等纯呈现元数据时记录其桌面验证范围，不计入 TC 业务语义。无法获得的值写未知，不编造 commit。

## 对应关系

| 原步骤/动作/断言 | 目标步骤或 TC | 处理 | 影响 |
|---|---|---|---|
| 实际来源位置或含义 | 实际文件与步骤 ID | 原样保留/共享提取/显式适配/未覆盖 | 对行为与环境的影响 |

特别列出 fixture、setup/teardown、mock、认证、事件顺序、分支、数据恢复、断言配置和自定义依赖的处理。对没有变化的普通动作可以合并描述，不要求逐行抄代码。

## 缺口与验证

- 已保留：有证据的原语义。
- 已适配：为什么需要改动，适配后边界是什么。
- 需要补齐：缺少的 Profile、依赖、预期或播放器能力，以及最小解除条件。
- 已验证：分别记录类型检查、清单静态解析/引用/编译、原 TC/共享或导出 TC、桌面真实回放及实际环境与证据路径。`--check-workspace` 的 typecheck/browser 均为 not-run，不能合并写成“全部验证通过”。
- 尚未验证：未执行的真实服务、视觉回放、数据恢复或客户现场检查。

最终状态采用“可在指定环境运行”“仅编译通过”“部分转换”或“依赖阻塞”等准确说法。不要把生成文件、测试收集成功或模拟页面通过写成客户验收完成。
