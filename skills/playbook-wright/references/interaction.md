# 内置播放与手动操作

内置播放和手动交接需要客户端 v0.6 或以上；`schemaVersion: 1` 不变。旧脚本默认继续使用独立 Chrome，新字段均可省略。

## 选择浏览器容器

在 `.playbook.ts` 的静态顶层对象中声明 `playback: { browser: 'embedded' }`，让页面在 Playbook 的内置浏览器中播放；`external` 或省略时使用原来的独立 Chrome。客户端可覆盖容器选择。一次 Book/Section 批量播放只采用一种容器，不能依赖脚本切换容器来延续登录态或页面。

内置容器展示真实受控页面，不是截图或录屏。它与日常 Chrome 以及独立播放会话不共享既有登录态。Profile 仍接收原生 Playwright page，仍逐脚本 prepare/release，批量共享同一个 BrowserContext；账号绑定、会话与资源清理由 Profile 保证。依赖 Chrome 扩展、特定启动参数或专有浏览器能力的 Profile 先验证实际兼容性，不因为支持内置就宣称所有场景已适配。

内置浏览器目前拦截网页自行打开的弹出窗口，避免跳出客户端。需要新窗口、多个独立 BrowserContext、Chrome 扩展或特定启动参数的流程，选择 external 并保留实际验证；不能把一次单页面教程通过当作所有浏览器特性已兼容。内置页面的会话与客户端界面分区隔离，批量内共享，下一轮重新开始。临时浏览器存储只按本轮精确路径与所有权标记回收；崩溃重启只处理持久索引中可核验且原 PID 已结束的目录，不扫描或猜测业务资源。

## 自动讲解与实操交接

需要观众操作的步骤增加静态 `interaction`：

```ts
interaction: {
  mode: 'manual',
  prompt: '现在可以亲自操作；完成后点击继续播放，也可以跳过本次练习。',
  timeoutMs: 10000,
  onTimeout: 'continue',
},
```

| 字段 | 语义 |
|---|---|
| mode | 只能是 `manual` |
| prompt | 可选的非空提醒文字；说明可做什么、是否可跳过以及如何继续 |
| timeoutMs | 0–300000 的整数，默认 10000 ms；0 等待用户明确继续 |
| onTimeout | `continue`（默认）或 `fail`；仅在有限倒计时耗尽时生效 |

桌面先完成当前旁白和操作前讲解，再交还鼠标、解除阻碍实操的引导遮挡并进入 `waiting`。手动步骤 **不自动执行 run**，避免再次点击、重复安装或未经用户操作写入。点击继续播放或全局播放/暂停快捷键可结束交接；超时按 onTimeout 处理。waiting 中暂停会冻结倒计时；页面真实 pointerdown/keydown 重置等待预算，避免用户操作时立即跳走。原生文件选择或真实 Skill 安装进行中冻结倒计时，结束后重新计时。停止、关窗和退出仍进入原有独立清理流程。

交接结束且未停止时，桌面调用：

```ts
verify(context, {
  interaction: { outcome: 'continued' /* 或 'timed-out' */, elapsedMs: 10000 },
});
```

`PlaybookStepOptions` 是 run/verify 的可选第二参，旧单参回调继续有效。elapsedMs 是该次交接实际经过时间，不是业务成功证据。`continued` 只表示用户明确继续，不表示已点击目标；`timed-out` 只表示等待到期。onTimeout 为 fail 时直接使该步失败，不执行后续步骤。continue 时仍执行 verify，有效业务断言失败也应失败，不能吞掉错误继续讲解。

先区分两种需求：

- **可跳过的体验**：例如“你现在可以安装 Skill，也可直接继续”。verify 核对仍可继续讲解的页面/状态；未安装必须保持“未安装”，不得把等待到期或继续点击记为安装成功。
- **必须完成的任务**：例如“请提交这份练习再继续”。用 `timeoutMs: 0` 或有限等待加 `onTimeout: 'fail'`，verify 检查真实结果。继续按钮本身不等于完成，不靠倒计时替代成功断言。

安装、删除、付款等真实动作保留实际界面的用户选择、目标预览、冲突提示和确认。不要在 manual 的 target、verify、Profile.prepare 或计时回调中藏入这些写入；Profile 只处理已授权的运行准备与释放。教程中的真实 Skill 安装由用户选择框架/范围/目录并主动点击，自动步骤仍使用练习数据，不能伪造“安装成功”界面。

## TC 与 PPTX 边界

`runPlaybook` 不等待人类，不读取内置容器，也不虚构 interaction 结果。它仍调用 `run(context)` 和 `verify(context)`，因此 manual 的 run 是明确的 TC 自动操作适配入口。要共用 TC，保留等价自动动作和真实断言；无法安全自动化时使用测试框架显式 skip/fixme 并写明原因，不能用空 run/verify 把未做的任务报成通过。独立 TC 展开同一等价路径，保留 fixture 和副作用授权。

PPTX 导出不支持含 manual 的执行，客户端会明确拒绝，不启动这些真人动作，也不自动跳过。需要课件时，另建已授权的纯自动演示副本，移除或替换 manual、提供对应 run/verify，核对写入与重播策略后再导出。不要为导出悄悄改写原来的交互式培训脚本。

验证时分别记录：元数据/类型、自动 TC、桌面实操。至少核对提前继续、自然超时、0 无限等待、暂停/停止、实际交互与 verify 失败；真实安装要区分取消、成功、冲突和失败，不将练习环境或按钮状态当作磁盘已安装证据。
