# 需求引导与脚本创作

## 先利用上下文，再补齐必要信息

从用户的话、当前业务项目、已有演示/测试、源码与可访问页面判断意图。已有脚本能满足时优先复用或调整，不从头复制一套业务流程。没有 TC 也可以从实际业务页面创作。

以下是需要理解的内容，不是逐项必问的表单：

| 维度 | 需要决定什么 | 常见信息来源 |
|---|---|---|
| 观众与目标 | 客户验收、培训或其他场景；希望观众理解什么 | 用户描述、项目与已有演示 |
| 业务范围 | 要演示的起点、核心操作、终点和价值 | 需求、现有流程、页面与测试 |
| 节奏 | 时长约束、章节、阅读停留与重点 | 用户描述与演示长度；未指定时采用合理默认并说明 |
| 环境与身份 | 实际地址、角色、登录与数据条件 | 项目配置、现有 Profile、私有凭据引用 |
| 写入与重播 | 是否创建/修改业务对象；再次播放如何恢复 | 真实动作与数据准备/清理逻辑 |
| 预期结果 | 每段如何判断有效，结束后应看到什么 | 业务契约、已有断言、实际结果 |

仅对会实质改变结果且无法读取核验的缺口提问。问题尽量聚焦在业务目标与范围，不让用户挑内部技术细节。目标清楚时直接生成与验证；可独立推进的内容继续推进，不把需求梳理变成每段都要批准的流程。

通常用一小段话说明观众、目标、流程与重要假设即可，放在回复、summary 或 explain 中；用户要求文档或任务确有复杂性时再独立记录需求。

## 生成流程

按当前契约生成 `.playbook.ts`：静态 default definePlaybook 对象、literal steps、稳定的流程/步骤 ID、业务标题、summary、dataMode/effects/replay/roles、目标 Locator、原生 run 与有意义的 verify。无 TC 来源时省略 source，不虚构原测试或版本。动态业务逻辑留在 callbacks/helpers 中，不能动态生成用于桌面发现的元数据。

把观众与执行身份分开：教师培训可以是面向教师的文案，但不自动表示页面需要 teacher 权限。requirements.roles 只声明实际执行需要由 Profile 绑定的身份角色；无需认证的合成页面使用空数组，观众写在 title/summary/explain。

先核实真实定位、状态和预期。使用实际已有的 Locator/helpers 或依据页面建立定位，不根据中文功能描述猜按钮标签。无页面访问、必要代码或环境时，交付明确缺口和已能完成部分，不能用 TODO 空函数冒充可播放脚本。

按观众能理解的业务节奏组织步骤：本章目标 → 控件用途与接下来的动作 → 原生操作 → 实际结果。只看结果的步骤可使用没有业务副作用的 run 并配有效 verify；不能用空 verify 或单纯“等待几秒”表示结果成功。

准备、登录、角色和清理由 `defineProfile` 及已有业务 helpers 提供。`prepare({ page, workspaceDir, parameters })` 读取工作区的实际配置，返回包含当前 page 的 context 和必要的 release；准备部分失败自行解绑自身 hooks。桌面负责创建和关闭浏览器/会话，Profile 不接管其生命周期。TC 继续沿用原 fixture，不把测试专用登录或数据库初始化静默变成客户现场逻辑。

交付项目根 `.playbook.json`，在 profiles 注册 Profile，在 scripts 注册文件、默认 Profile 和标签；用 books → sections → scripts 按稳定流程 ID 编排。Book 和 Section ID 使用字母、数字、点、下划线或连字符，Section 在 Book 内唯一。Book“播放全部”按章节和各章脚本的数组顺序执行，Section“播放全部”按自身脚本数组执行；容器不复制 run/verify。

批量执行统一使用所选同一 Profile，脚本与 Profile 的数据模式、角色要求保持兼容。每个脚本独立准备与释放，不能把上个脚本创建的页面或内存变量当作下一脚本的前置条件；有业务依赖时由 Profile 或明确的持久数据条件提供。旧 demos 由客户端兼容读取为 Book/Section，不为接入新版本而擅自改写旧清单。

清单参数不存密码；私有配置相对 workspaceDir 解析，不复制到产品仓库。已有清单时做最小增量维护，不重写无关资产。进度条、活动显隐和全局快捷键由客户端提供，脚本只描述页面引导与业务流程。

## 验证与交付

先按业务项目方式做类型检查，再通过 Playbook `--check-workspace` 核对静态元数据、引用和编译；后者不执行 typecheck 或浏览器。具备已授权环境时实际播放并核对关键状态和呈现。UI 操作新写入时至少验证核心结果与失败传播；仅改讲解和元数据时按影响验证，不机械跑无关测试。

回报清单、脚本、Profile、假设、准备/运行方式、dataMode 与业务副作用、已验证/尚未验证内容。用户从桌面添加含清单的工作区即可发现资产；环境或视觉尚未运行时明确说明，不以静态发现成功代替可播放结论。
