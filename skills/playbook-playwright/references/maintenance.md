# 脚本管理、讲解与呈现调整

## 定位要改的资产

优先使用用户给出的文件、流程 ID、步骤 ID 或客户端反馈的版本与错误；只给业务名称时搜索现有资产。相邻文案不是唯一标识，不能凭“第二步”去修改另一个脚本。若反馈版本与当前代码不同，先核对差异，保留历史运行结论。

变更只作用于用户要求的范围。Playbook 客户端是只读消费者；修改应由智能体写入业务侧资产，不修改客户端缓存来假装源文件已经更新。

## 管理与编排

- 改标题或文件名时保留稳定 ID，除非用户明确要改变身份；同步实际存在的 imports、演示引用和发现元数据。
- 拆分、合并和调整顺序前检查上下文、事件注册、前置数据与清理。不能让步骤失去依赖，或把同一个写入动作重复执行。
- 删除按用户授权范围处理，并先检查调用方。若仍被 TC 或演示引用，处理相应引用或说明需要保留的依赖，不删除不相关测试。
- 演示组合在 `.playbook.json` 的 demos 中按流程 ID 引用 scripts，不复制 run/verify。同步默认 Profile、数据类别与依赖；组合演示只使用同一个 Profile，各脚本所需角色必须由它实际提供。

## 把自然语言调整映射到受支持字段

| 用户意图 | 当前契约中的处理 |
|---|---|
| 开场或章节更适合某类观众 | 调整 title、summary、explain 与 presentation.chapter；保持业务事实 |
| 讲解更短、更多解释或更突出功能价值 | 修改对应 explain，避免改变预期结果 |
| 某步多停留/少停留 | 调整该步 presentation.holdMs，毫秒为单位；“多四秒”在当前有效值上增加 4000 |
| 结果页面多展示几秒 | 调整该步 presentation.afterMs；它在 run 和 verify 成功后执行 |
| 所有步骤的讲解节奏 | 调整流程 presentation.defaultHoldMs；单步 holdMs 仍优先 |
| 开场长短 | 调整流程 presentation.openingMs |
| 提示移到下方/左侧等 | 修改 presentation.side 为 bottom/left 等现有枚举 |
| 展示哪个组件 | 仅在确需改变引导目标时调整 target；原业务 run 的定位不随之暗改 |
| 蒙层深浅、光圈大小、光标速度 | 调整流程 presentation.overlayOpacity、spotlightRadius、cursorMoveMs；数值范围见契约 |

当前有效停留值未写在步骤里时，先查实际播放器/演示配置的默认值；不能把“增加四秒”擅自解释为“总共四秒”。如果默认值无法确定且会影响结果，聚焦询问该值或预期总时长。时长与范围明确时自行处理。

区分点击前讲解的 holdMs 与结果验证后的 afterMs。未指定步骤 holdMs 时先用流程 defaultHoldMs，再用播放器默认 2600；afterMs 默认 550。需要“增加四秒”时在实际生效值上加 4000，不改成总共四秒。

桌面已支持蒙层、聚光、光标移动、点击效果、开场、章节与上述时长字段；无呈现的 runPlaybook 参考执行器不渲染它们。当前没有通用主题、语音或可视化脚本编辑器字段，不凭空添加键或修改业务页面 CSS。若确需产品扩展，先按用户目标确定最小范围；元数据改好但未实际播放时，只报告字段已更新。

呈现层只展示说明和光标，不执行第二遍业务点击。不把页面结果等待换成 holdMs，不用放宽断言让播放显得更流畅。逐字输入与 fill 的业务事件语义不同，不能仅为动画效果直接替换。

## 反馈修复与验证

失败先分清是业务状态、Locator、前置环境还是呈现层问题，使用实际记录和页面核对。客户脚本问题在业务资产中修复，通用播放器缺陷在产品范围内处理，不为视觉问题顺便改业务功能。

纯说明/呈现变更对比修改前后的 run/verify 与上下文，确认语义未改；执行必要的类型与清单检查。`--check-workspace` 只核对静态元数据、引用与编译，不是 typecheck/browser 通过。涉及目标、顺序、操作或前置数据时重验受影响流程；实际播放检查目标唯一性、说明遮挡和结果阅读阶段。未渲染时写“元数据已调整，视觉回放未验证”。

客户端按运行快照播放，源清单、脚本、Profile 或静态相对 imports 更新影响下一轮；复制客户端上下文可取得流程、工作区、运行记录与 Skill 版本供用户自己的智能体接续。核对实际文件/步骤 ID、源版本与失败记录，不改历史结论，也不宣称更新了当前正在执行的浏览器流程。
