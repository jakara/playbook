# 脚本管理、讲解与呈现调整

## 定位要改的资产

优先使用用户给出的文件、流程 ID、步骤 ID 或客户端反馈的版本与错误；只给业务名称时搜索现有资产。相邻文案不是唯一标识，不能凭“第二步”去修改另一个脚本。若反馈版本与当前代码不同，先核对差异，保留历史运行结论。

变更只作用于用户要求的范围。Playbook 客户端是只读消费者；修改应由智能体写入业务侧资产，不修改客户端缓存来假装源文件已经更新。

## 管理与编排

- 改标题或文件名时保留稳定 ID，除非用户明确要改变身份；同步实际存在的 imports、演示引用和发现元数据。
- 拆分、合并和调整顺序前检查上下文、事件注册、前置数据与清理。不能让步骤失去依赖，或把同一个写入动作重复执行。
- 删除按用户授权范围处理，并先检查调用方。若仍被 TC 或演示引用，处理相应引用或说明需要保留的依赖，不删除不相关测试。
- 演示组合引用现有流程，不再复制 run/verify。沿用项目实际已实现的演示配置格式；格式未固化时明确列出组合方案和接入缺口，不声称存在一键播放入口。

## 把自然语言调整映射到受支持字段

| 用户意图 | 当前 v0.1 契约中的处理 |
|---|---|
| 开场或章节更适合某类观众 | 调整 title、summary、explain 与 presentation.chapter；保持业务事实 |
| 讲解更短、更多解释或更突出功能价值 | 修改对应 explain，避免改变预期结果 |
| 某步多停留/少停留 | 调整该步 presentation.holdMs，毫秒为单位；“多四秒”在当前有效值上增加 4000 |
| 提示移到下方/左侧等 | 修改 presentation.side 为 bottom/left 等现有枚举 |
| 展示哪个组件 | 仅在确需改变引导目标时调整 target；原业务 run 的定位不随之暗改 |

当前有效停留值未写在步骤里时，先查实际播放器/演示配置的默认值；不能把“增加四秒”擅自解释为“总共四秒”。如果默认值无法确定且会影响结果，聚焦询问该值或预期总时长。时长与范围明确时自行处理。

区分点击前讲解的停留与打开结果后供观众阅读的停留。按实际意图选择受支持的阶段或结果展示步骤；没有相应能力时明确缺口，不能只增加点击前等待便宣称结果页面已多展示几秒。

v0.1 契约目前只定义 chapter/side/holdMs，不包含蒙层透明度、光圈大小、光标速度、主题等字段；参考执行器也不渲染这些效果。对这些需求先检查实际项目播放器是否已扩展相应契约，存在则按其真实支持处理；没有则列出需扩展的播放器能力。不要凭空添加键、修改业务页面 CSS 或承诺效果已生效。只有用户授权产品扩展时才进入播放器实现范围。

呈现层只展示说明和光标，不执行第二遍业务点击。不把页面结果等待换成 holdMs，不用放宽断言让播放显得更流畅。逐字输入与 fill 的业务事件语义不同，不能仅为动画效果直接替换。

## 反馈修复与验证

失败先分清是业务状态、Locator、前置环境还是呈现层问题，使用实际记录和页面核对。客户脚本问题在业务资产中修复，通用播放器缺陷在产品范围内处理，不为视觉问题顺便改业务功能。

纯说明/呈现变更对比修改前后的 run/verify 与上下文，确认语义未改；执行必要的类型检查。涉及目标、顺序、操作或前置数据时重新验证受影响流程；具备真实播放器时检查目标页面的效果和遮挡。没有渲染验证时准确写“元数据已调整，视觉回放未验证”。

客户端运行中修改只影响下一轮。回报实际文件/步骤 ID、改了什么、保留的动作与断言、验证结果及需要重播的版本，不宣称自动更新了当前正在执行的浏览器流程。
