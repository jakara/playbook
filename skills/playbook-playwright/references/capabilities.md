# 可用功能与选择方式

适配播放器 v0.3 系列、Skill 0.5.2，清单/脚本/Profile 的 `schemaVersion: 1`。本页是功能入口；完整类型、数值范围与生命周期以 [契约](contract.md) 为准。先依据用户目标挑选所需能力，不把整张清单变成必答问卷，也不默认给所有脚本加语音或打码。

## 项目、内容与创作

| 用户想做什么 | 当前能力与用法 |
|---|---|
| 给客户验收或培训演示系统 | 从自然语言、手工操作或已有 TC 创作。每步原生 `run` 执行动作，`verify` 检查真实结果；Profile 提供实际环境、角色、准备与释放 |
| 管理演示资产 | 智能体在业务项目中创建、改名、拆分、合并、删除、调整顺序与讲解。客户端负责查看、搜索、播放和反馈；业务脚本与录音留在业务仓库 |
| 按文件夹放几本操作手册 | 一个“项目”就是含 `.playbook.json` 的本地文件夹，workspace 指同一目录。左侧仅“项目文件夹 → Book”两层树；没有独立资料库，不另造项目数据库 |
| 看 Book 和章节 | 进入时先显示 Book 列表；选中 Book 后左栏收窄保留标题，右侧展示详情。Section 是 Tab（支持左右方向键及 Home/End），脚本在对应 Tab 下平铺，可进入步骤详情；Section/脚本不嵌进左树 |
| 连续播放一整本或一节 | 清单 `books[].sections[].scripts` 引用流程 ID。Book“播放全部”按章节及脚本数组顺序执行，Section“播放本节”按本节脚本数组执行，单脚本也可播放 |
| 选择环境或账号角色 | 客户端选择已有 Profile，智能体维护 `.profile.ts` 和清单注册。整次批量播放使用同一所选 Profile，各脚本单独 prepare/release；不能依赖上一脚本的 page 或内存 |
| 查找、定位、继续修改 | 按名称、摘要、标签、角色搜索，查看说明、步骤、数据类别、副作用和重播要求；定位源文件或复制修改/错误上下文，再由用户交给自己的智能体 |

一次批量播放共享 BrowserContext；每个脚本创建新 page、重新 prepare/release 和构造业务 context，不保证 cookie 或登录会话完全隔离。Profile 要依据实际身份与数据要求处理和验证这一边界。

Book/Section 只是引用与顺序容器，SDK `definePlaybook()` 表示其中一个可执行脚本。不要把章节容器写成执行函数，不复制动作。旧 `demos` 清单兼容读取为 Book/Section，未要求迁移时保留原资产。具体生成方法见 [创作](authoring.md)，编排与改名见 [维护](maintenance.md)。

## 页面引导与节奏

| 观看效果 | 脚本如何表达 | 实际行为 |
|---|---|---|
| 开场中央大字 | 流程 `title`、`summary`；`presentation.openingMs` | 每个脚本先介绍目标。默认停留 2800 ms；语音启用时也等待开场语音完成 |
| 中途介绍下一段 | 步骤 `presentation.chapter` | 章节名称变化时居中介绍下一段；这是脚本内部章节文案，独立于清单 Section Tab |
| 组件旁箭头说明 | 步骤 `target(context) => Locator`、`title`、`explain`、`presentation.side` | target 必须唯一且可见，播放器滚动定位并展示 top/right/bottom/left 提示；target 只定位，动作仍由 run 执行 |
| 中央说明、不指向控件 | 省略该步 `target` | 显示居中文案。观察步骤可不写入业务数据，但仍需有意义的 verify |
| 灰色半透明蒙层 | 流程 `presentation.overlayOpacity` | 默认 0.56，可调深浅；不修改业务页面主题 |
| 鼠标附近聚光、柔边 | 流程 `spotlightRadius`、`spotlightFeather`，均在 presentation 中 | 默认半径 105 px，柔边 24 px；柔边 0 为硬边。光圈随演示光标移动，鼠标光晕与点击波纹由播放器提供 |
| 光标慢一点 | 流程 `presentation.cursorMoveMs` | 默认 900 ms；仅调整呈现，不把原有 fill 改为逐字键盘输入，也不重复点击 |
| 操作前多讲几秒 | 流程 `presentation.defaultHoldMs` 或步骤 `presentation.holdMs` | 默认 2600 ms，步骤覆盖流程。先显示提示、阅读/语音与光标演示，再执行动作；语音未完不会提前操作 |
| 操作后停留看结果 | 步骤 `presentation.afterMs` | run 与 verify 成功后停留，默认 550 ms。它不负责等待接口、导航或结果就绪 |

时间单位均为毫秒；允许范围见 [字段与呈现](contract.md#字段与呈现)。需要“多四秒”时在当前生效值上增加 4000。若需要打开弹窗后再指着内容讲解，先保留打开与验证步骤，再增加指向已打开内容的观察步骤及有效断言；当前步骤语音发生在其 run 之前，不能只改 afterMs 让它自动变成操作后的旁白。

## 页面打码

流程顶层 `redactions` 数组按实际页面的 **CSS selector** 声明目标，不能放进某个 step，也不是 Locator 字符串：

```ts
redactions: [
  { selector: '.brand-logo', mode: 'cover', label: '演示品牌', padding: 2 },
  { selector: '.customer-name, .account-number', mode: 'cover' },
  { selector: '.organization-name', mode: 'blur', blurPx: 12 },
],
```

以上选择器只是字段示例，必须换成当前业务页面真实、稳定的目标。cover 是默认不透明遮盖，可选安全的替代 label；blur 是视觉模糊，blurPx 默认 12。cover 的 padding 默认 2 px。一个选择器可覆盖多处匹配，规则随滚动、重渲染、原生 dialog 与同一主页面导航保持，覆盖层不拦截原生交互。

打码只影响观看画面，原值仍在 DOM/API/业务存储中；模糊也可能被辨识。讲稿、提示和录音不得复述实际敏感值。更高保密要求要使用适当的演示数据/环境；不要把视觉遮盖当成数据安全措施。frame、新窗口和封闭 Shadow DOM 中的目标未提供通用打码适配，必须核对实际范围。

## 同步语音

语音默认关闭。启用流程朗读可复用既有讲解：

```ts
narration: { enabled: true, voice: 'Tingting', rate: 185 },
```

步骤内可按需选择一种写法：

| 配置 | 用途 |
|---|---|
| `narration: { text: '这里展示已有的课堂任务。' }` | 使用单步讲稿 |
| `narration: { audio: 'demos/audio/task.wav' }` | 播放本地录音 |
| `narration: false` | 跳过本步语音 |

开场默认读流程 title 与 summary，每步默认读 explain；流程 `narration.opening` 可为 `{ text }`、`{ audio }` 或 `false`。步骤对象可在流程未启用时单独开启该步；显式 opening 对象也可单独开启开场。text 与 audio 互斥，false 跳过对应语音。

- **自动朗读**：当前使用 macOS 本机已安装声线，默认 Tingting、185 words/min，rate 是 80–400 的整数。无需云账号；其他平台本轮使用本地录音，不宣称已适配系统 TTS。
- **已有录音**：audio 是相对业务工作区根目录的路径，支持 wav/mp3/m4a/ogg，每个文件最多 20 MB；禁止网络 URL、绝对或越界路径。录音随本轮快照冻结，下一轮才采用源文件更新。
- **同步方式**：语音配合当前提示和光标播放，当前讲解与最短视觉停留均完成后再操作。暂停/继续/停止同步控制语音；生成或播放失败会停止该轮，不静默跳过。改变 rate 只调整系统朗读，不给已有录音变速。

不承诺云端配音、声音克隆、连续背景音乐或跨步骤混音。讲稿长短影响实际总时长；不能只缩短 holdMs 来截断旁白。文件有效、媒体时间推进与人耳试听是不同证据，分别报告。

## 客户端已有的全局控制

以下由客户端提供，**无需新增脚本字段、页面按钮或键盘 hook**：

| 能力 | 用户如何使用与边界 |
|---|---|
| 独立浏览器 | 使用本机 Google Chrome 的独立会话展示真实页面；不是内嵌 WebView，不连接日常 Chrome 登录态。打包应用携带运行环境，无需用户另装 Node 服务 |
| 全局播放栏 | Electron 原生置顶悬浮条显示流程、步骤和进度，业务页面仅注入引导层 |
| 自动显隐 | 约 3 秒无鼠标/键盘活动后隐藏，活动后显现；终态隐藏。系统只提供活动状态，不记录键盘内容 |
| 拖动、收起与展开 | 拖动文字或空白区域；“−”收成保留暂停/继续的小条，“↗”展开。位置与收起状态在本次应用会话保留，显示器范围变化时调整到可见区域 |
| 系统播放/暂停 | 默认 `CommandOrControl+Alt+P`，Mac 为 `⌘⌥P`。空闲时播放主界面当前选择，运行中暂停/继续，终态可重播；均经过原有环境和重播校验 |
| 恢复演示窗口 | 继续时恢复最小化的受控 Chrome，并请求将本轮页面置前，再继续调度；较新的暂停/停止覆盖尚未完成的继续请求 |
| 停止与重播 | 暂停在可停边界生效，已发出的业务操作不自动撤销；停止阻止后续调度。终态从头重播仍受 safe/reset-required/single-run 约束 |

快捷键注册失败会在客户端提示。跨应用焦点、实体输入、全屏/多显示器与不同系统的效果须按真实环境验证，不能把注册成功当成实体按键验收。若用户报告播放栏或焦点故障，先区分客户端/系统问题，不向业务脚本硬塞控制栏、拖拽逻辑或伪造系统快捷键配置。

## 文件更新、反馈、测试与 Skill 分发

| 能力 | 正确使用 |
|---|---|
| 只读与更新发现 | 客户端定期重新发现资产，显示变更；演示源文件由用户的智能体维护。移出项目只移除登记，保留文件 |
| 本轮快照 | 本轮使用已构建的代码、步骤和录音快照，源文件修改下一轮生效。不要修改应用缓存假装修改了脚本 |
| 结果反馈 | 查看成功/失败/停止记录、进度、耗时和错误，复制上下文交给用户自己的智能体；客户端不自动发送消息或上传模型 |
| TC → script | [保留 fixture、动作、断言与事件顺序并适配 Profile](tc-to-playbook.md)，再添加演示说明与效果；不承诺任意 TC 一键无损转换 |
| script → TC | [共享 runPlaybook 或独立展开 run/verify](playbook-to-tc.md)，保留测试生命周期。TC 不播放语音、引导、打码或阅读动画；Book/Section 先按引用顺序展开 |
| 随包 Skill 安装 | 客户端“Skill 安装”支持 Codex/Claude Code 的个人或指定项目范围；项目通过“选择文件夹/更换文件夹”指定，不限已登记的演示目录，也不要求 .playbook.json。Codex 追加 .agents/skills/playbook-playwright，Claude Code 追加 .claude/skills/playbook-playwright，不自动猜测上级仓库；选择和取消不写文件、不登记演示项目。预览版本、目标与冲突，更新先备份，修改内容须明确选择替换；软链接不写入 |
| Skill 生效 | 安装只核验文件落盘，不自动修改模型、全局规则或 hooks。更新后在目标智能体重新加载/开启新会话并确认调用；既有会话不会自动获得新版本知识 |

声明 read-only 或重播策略不会自动拦截写入或重置业务数据，Profile 必须实现对应保障。`--check-workspace` 只做静态发现/引用/编译，独立类型检查、TC 回归、真实浏览器播放和人耳/实体输入验收分别记录；详见 [验证](contract.md#运行与验证)。业务副作用的授权与账号边界始终保留。
