# Playbook 产品方案 v0.2

日期：2026-10-21。本文是产品与实现方案；Electron 客户端和 Skill 安装器尚未实施。

## 产品定位

Playbook 是供智能体创作、供用户观看与播放的自动演示工具。用户使用自己的智能体，配合 Playbook Skill，把业务目标、已有测试或手工讲解过程整理为可重复播放的 Playbook scripts；桌面客户端发现这些文件，提供查看、搜索和真实浏览器回放。

AI 原生体现在创作与维护流程：需求梳理、脚本生成、讲解修改、演示效果调整、流程编排、测试转换与失败修复，均通过用户熟悉的智能体完成。Skill 是主要创作入口，客户端是资料库和播放器。应用无需内置模型账户、聊天窗口或另一套智能体运行时。

核心价值保持不变：客户验收和培训中，系统先介绍业务目标，再以箭头提示说明入口与功能，配合灰色蒙层和鼠标光圈，自动执行真实操作，检查结果后继续下一步。业务流程与测试复用相同的原生 Playwright 动作和断言。

首个试点为艺工平台。艺工脚本归属艺工业务仓库；Playbook 产品不内置学校、账号、菜单、URL 或课程数据。

## 职责边界

| 需求或动作 | 主要执行者 | 客户端作用 |
|---|---|---|
| 梳理给谁看、讲什么、展示哪些流程 | 用户的智能体 + Skill | 提供使用引导与可复制请求示例 |
| 新建、改名、拆分、合并、删除脚本 | 用户的智能体 + Skill | 发现文件变化、更新只读列表 |
| 调整标题、讲解、章节、步骤顺序和演示组合 | 用户的智能体 + Skill | 展示最终内容并播放 |
| 调整停留时间、箭头方向、光圈与蒙层等支持的效果 | 用户的智能体 + Skill | 按已发布的呈现契约执行 |
| 实现定位、动作、断言、Profile 和数据准备 | 用户的智能体 + Skill | 预检、运行并呈现结果 |
| TC 与 Playbook scripts 双向转换 | 用户的智能体 + Skill | 查看来源、步骤与验证状态 |
| 查看、搜索、选择环境、播放、暂停、停止和重播 | 客户端 | 提供直接操作 |
| 安装或更新随应用内置的 Skill | 客户端，按用户指示 | 处理目标框架、范围、版本、冲突与结果 |

客户端对脚本、演示配置及业务源码保持只读。用户选择工作区、切换已有环境和控制本轮播放属于客户端操作，不修改脚本真源。应用可写自己的索引缓存、偏好、运行记录与构建缓存，并按明确操作安装 Skill。

脚本只读描述的是客户端对创作文件的处理；播放中是否修改业务系统，由脚本声明、环境与动作决定。不能因为客户端没有编辑器，就把业务写入流程标成只读。

## 用户与资产

| 对象 | 用途 | 归属 |
|---|---|---|
| 业务工作区 | 脚本、环境与项目依赖根目录 | 业务仓库或用户选择的目录 |
| Playbook script | 业务流程、原生动作、断言与步骤说明 | 智能体生成/维护，随业务代码演进 |
| Profile | URL、角色会话、准备与释放逻辑 | 业务侧维护；私密值本地保存 |
| 演示配置 | 脚本引用、顺序、章节与呈现选项 | 智能体生成/维护，客户端只读 |
| 发现清单 | 名称、摘要、标签、来源与文件版本等静态元数据 | 创作流程生成，客户端用于浏览与搜索 |
| 运行记录 | 版本、环境类别、步骤状态与失败原因 | 本机保存，按需导出或交给智能体分析 |
| Skill 包 | 需求引导、创作、调整和转换能力及契约说明 | 随客户端分发，按用户指示安装 |

业务文件是事实来源。客户端缓存可以重建，不形成另一份可编辑脚本库。发现清单、演示配置和效果参数的具体格式需与播放器一起固化；当前已实现的脚本契约仍为 v0.1，不能把设计字段当成已经可运行的接口。

## 端到端使用流程

### 首次使用：安装 Skill

1. 用户打开客户端，进入“智能体 Skill”。应用展示内置 Skill 的版本、能力、兼容的脚本/播放器版本及已实现支持的本地框架。
2. 用户选择目标框架，选择用户级或指定项目级范围。应用检测候选位置，并允许在适配器支持范围内选择自定义位置。
3. 应用展示实际目标目录、将安装的文件、已有版本及冲突处理。用户的安装指示是这次写入的授权，不自动安装到所有检测到的框架。
4. 用户确认目标后，应用从本地内置包安装、核验文件与版本，显示成功或具体失败原因。更新时先备份并核验可恢复性，再进行替换。
5. 应用给出适合目标框架的使用示例，以及该框架是否需要重新加载的说明。文件已安装与智能体已实际加载分别显示，不能仅凭复制成功就宣称生效。

Skill 随应用打包，首次安装不依赖用户去其他网站下载。用户可选择多个已支持框架，但每个目标的结果独立显示。未支持的框架可打开内置包位置并提供手动说明，不能静默猜测其配置规则。

### 创作：把需求交给自己的智能体

用户可以直接描述业务意图，例如：“给客户讲一遍教师怎么查课程、核对设计并预览任务，控制在三分钟内；也可以参考已有 TC。”

Skill 先读取可用的项目、测试、页面和环境上下文，识别已有脚本能否复用。仅对会改变结果且不能自行核验的缺口提问：观众与目标、必须覆盖的流程、时长或节奏、环境与数据操作边界等。已知信息不重复询问，不要求用户填写固定长表。

智能体据此形成简短的演示意图，选择实际业务路径，生成或更新 scripts、必要的环境适配与演示配置；目标清楚时直接实施和验证。需求摘要通常保留在对话和脚本元数据中，复杂任务才另存文档。

支持三种输入：自然语言需求、现有手工演示流程、Playwright TC。没有 TC 时，智能体依据真实页面、源码和已知业务预期生成动作与断言，不虚构选择器或成功条件。

### 观看：客户端发现并播放

1. 用户在客户端添加业务工作区。客户端读取发现清单并展示脚本与已编排演示。
2. 用户按名称、业务关键词、标签、角色或来源搜索，查看章节、说明、环境类别与最近运行结果。
3. 选择已有 Profile，执行预检后播放。独立 Chrome 展示中央开场、箭头提示、灰色蒙层、光标光圈与原生自动操作。
4. 每步实际断言通过后继续；可暂停、继续、停止和从头重播。数据恢复要求保持显式。
5. 结束后查看已完成项或失败步骤；需要调整时复制上下文给自己的智能体。

### 迭代：自然语言反馈，再播放验证

用户可以对自己的智能体说：“第二段太快，任务预览多停四秒，提示放到下方，开场更适合第一次使用的老师。”

Skill 定位到对应脚本与稳定步骤 ID，读取当前契约支持的呈现项，只修改相关说明或参数，保留业务动作和断言。超出已支持效果能力时说明所需播放器扩展，不能写入未知配置后宣称生效。

客户端监听资产变化并更新视图。正在运行时冻结本轮脚本、配置与依赖版本；新修改只用于下一轮，不能把半轮新脚本混进当前播放。执行中的变更显示“有更新，下一轮生效”。

失败场景同样闭环：客户端提供可复制的文件位置、流程/步骤 ID、运行版本、错误和脱敏记录路径；智能体查看实际证据、修复并验证。客户端不自动给其他智能体发消息，也不自动上传业务资料。

## Skill 的产品职责

Skill 统一提供四类工作：

1. **创作**：理解观众与目标，从自然语言、手工流程或已有资产导出 Playbook scripts。
2. **维护**：查找、重命名、拆分、合并、调整讲解与效果、组织演示，维护引用和发现元数据。
3. **测试复用**：TC → Script、Script → 共享或独立 TC，保留 fixture、事件顺序、断言、数据边界与清理。
4. **验证与修复**：根据页面、类型检查、实际运行和失败记录判断结果，保留无法自动适配的缺口。

Skill 需要理解所支持的脚本与呈现版本，提供少量可用样例和对话引导。它不绑定某一家模型服务，也不替代智能体自身的文件、浏览器和执行工具；缺少工具或环境时准确报告限制。

安装包中的 Skill 与应用共同发布，独立标识版本和兼容范围。更新应用不自动覆盖用户改过的 Skill；脚本契约升级也不自动改写业务资产，由智能体在用户授权范围内迁移。

## 客户端页面

| 页面 | 内容 | 允许操作 |
|---|---|---|
| 资料库 | 工作区、脚本与演示列表、关键词和标签 | 添加/移除工作区登记、搜索、筛选、刷新 |
| 脚本/演示详情 | 目的、章节、步骤说明、效果摘要、来源、环境与版本 | 只读查看、打开源文件所在位置、复制修改上下文、播放 |
| 播放控制台 | 本轮进度、当前步骤、环境与结果 | 暂停、继续、停止、从头重播 |
| 运行记录 | 已完成项、版本、失败步骤、证据 | 查看、定位源文件、按需导出脱敏上下文 |
| 智能体 Skill | 内置版本、支持框架、安装目标与状态 | 安装、更新、核验、必要时恢复备份 |

客户端不提供脚本编辑表单、章节排序面板、讲解编辑器、效果调节滑块或演示组合编辑器。可提供“复制修改请求”“如何让智能体调整”等轻量入口，帮助用户回到自己的创作环境。

## 架构决策

- 用户自己的智能体 + Skill 构成创作端；业务文件是两端协作接口，无需应用接入另一套模型 API 或常驻创作服务。
- Electron 承担只读资料库、搜索、播放与 Skill 分发。Node 环境随应用交付，独立运行器负责 Playwright 和资源生命周期。
- Playwright 保留原生定位、动作与断言；Driver.js 加产品呈现层负责引导效果。脚本不重建浏览器自动化引擎。
- 清单与元数据用于只读发现；客户端不在主进程为了展示标题而直接执行未知业务模块。播放仍限于用户明确接入的受信任工作区。
- 写入范围按模块收窄：资料库不写业务资产；运行器只写自己的缓存/记录；Skill 安装器只在用户选定且预览过的目标内写入随包 Skill，并有更新备份和结果核验。
- 界面、运行器、Skill 适配器与包版本解耦。安装器验证目录与文件，不承诺让任意未知框架自动识别 Skill。

## 首版范围与非范围

| 能力 | 首版要求 |
|---|---|
| AI 创作 Skill | 需求引导、脚本生成与维护、效果调整、双向转换和验证指导 |
| 内置 Skill 安装 | 从本地资源安装到已支持框架；目标/范围选择、版本与冲突说明、备份、核验 |
| 只读资料库 | 登记业务目录、发现资产、搜索筛选、查看步骤与来源、感知文件变化 |
| 真实回放 | 已有 Profile 选择、Chrome 独立会话、引导呈现、暂停停止、结果校验和重播 |
| 运行反馈 | 本轮版本与环境类别、失败步骤、可复制给智能体的脱敏上下文 |
| 分发 | macOS 首发；不单独启动 Node 服务；缺失业务依赖有明确指引 |

首版不包含应用内聊天/模型账户、客户端脚本编辑与演示编排、可视化效果编辑器、自动安装到所有框架、自动改写智能体全局规则、云端同步协作、视频剪辑、语音合成、浏览器扩展或原生桌面程序自动化。

多页面、跨域 frame、上传下载和操作系统对话框的演示支持仍需单独验收。底层 Playwright 有相应能力，不等于当前播放器全部支持。

## 用户故事

1. 作为交付人员，我希望向自己的智能体描述要展示的业务，由 Skill 帮我补齐真正缺失的信息并生成脚本。
2. 作为培训人员，我希望用自然语言调整讲解、节奏和效果，再回到客户端观看结果。
3. 作为开发者，我希望把已有 TC 与演示共享原生业务流程，保持断言和数据边界。
4. 作为演示者，我希望快速搜索并播放已完成的脚本，客户端不要求我操作复杂编辑工具。
5. 作为用户，我希望从应用直接把内置 Skill 安装到我选择的本地智能体，不必另外下载。
6. 作为使用多个智能体的人，我希望明确每个安装目标的版本、冲突与结果，已有自定义不被静默覆盖。
7. 作为项目负责人，我希望演示版本、真实/模拟环境和失败结果清楚可追溯。

## 验收与交付阶段

| 场景 | 通过条件 |
|---|---|
| 需求到脚本 | 无 TC 的需求也能经 Skill 引导生成匹配当前契约的脚本，关键动作与预期有真实依据 |
| 自然语言调整 | 智能体仅修改目标说明/呈现；原动作与断言保留；下一轮正确使用新版本 |
| 客户端只读 | 浏览、搜索、预检与播放前后，业务脚本、配置和源码内容不变；构建结果写到应用缓存 |
| 变化发现 | 资产新增/改动/删除后列表更新；无效清单或断裂引用明确提示，不自动修复源码 |
| 安装与更新 | 离线随包安装；只写所选目标；已修改文件不被覆盖；备份可恢复；逐目标核验 |
| 加载状态 | 安装成功与框架加载区分；无法探测的加载状态明确标为待验证 |
| 播放与失败 | 真实检查控制前进；暂停停止符合安全边界；失败后不宣称完成；按数据策略重播 |
| 版本固定 | 本轮不受中途修改影响；记录脚本、配置和依赖版本，下一轮重新预检 |
| 双向转换 | 三种 TC 正向结果一致；刻意破坏预期后均失败 |

实施顺序：

1. **方案与 Skill 调整（本轮）**：确定 AI 创作与只读客户端边界，扩展需求引导、创作和调整说明；保留现有 v0.1 契约和转换代码。
2. **桌面播放与分发闭环**：固化发现/演示/呈现契约，内置 Skill 包，完成安装适配与只读资料库，验证打包后浏览器启动和单流程播放。
3. **反馈与多流程使用**：文件变化发现、演示组合的只读展示、搜索、版本固定、运行记录与反馈上下文。
4. **业务试点与发布**：接入艺工资产，验证真实本地业务、重播恢复、干净机器安装、签名公证与离线包。

现有契约和合成用例证明的是参考流程与转换方式；更新后的创作 Skill 需分别验证需求引导与调整行为。Skill 安装器、Electron 界面和完整播放器仍待实施，历史测试结果不能作为这些新能力已完成的证据。
