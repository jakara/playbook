# Playbook 产品方案 v0.1

日期：2026-10-21。本文是产品与实现方案，不表示 Electron 应用已交付。

## 产品目标

在客户验收、售前演示和培训中，把“人手操作并持续讲解系统”变为“选择预设流程，一键播放”。观看者看到的是正在运行的真实系统：先介绍本段业务，再指出目标控件、解释用途，移动演示光标并自动操作，等待真实结果后进入下一步。

成功的结果包括三个方面：演示者可以稳定重复展示核心业务；开发者能够复用已有 Playwright 测试资产；业务流程变化后，测试与演示不需要各维护一份操作逻辑。

首个试点是艺工平台。艺工专有脚本留在艺工业务仓库；Playbook 产品对学校、角色、菜单、URL 和课程数据均不做内置假设。

## 用户与使用场景

| 用户 | 需要完成的事 | 获得的结果 |
|---|---|---|
| 项目交付与验收人员 | 选择客户环境、账号角色和核心流程，自动演示 | 减少重复讲解，知道每一步是否真正完成 |
| 培训人员 | 连播多个流程，在关键处暂停并答疑 | 看得清用途、入口、动作和结果 |
| 开发与测试人员 | 从 TC 提取可演示流程，或把演示纳入回归测试 | 复用定位、动作、断言与准备逻辑 |
| 其他智能体 | 根据统一契约转换脚本并报告缺口 | 产生可审阅、可执行的资产，而非表面相似的代码 |

## 核心概念与归属

| 对象 | 含义 | 保存位置 |
|---|---|---|
| 工作区 | 某个业务项目的脚本、环境配置和依赖根目录 | 业务仓库或用户选择的本地目录 |
| Playbook script | 一段可重复执行的业务流程，含原生动作、断言和演示说明 | 业务仓库，随业务版本演进 |
| 环境配置 Profile | URL、浏览器、角色与账号绑定、准备和释放逻辑 | 业务侧可提交非敏感模板，私密值本地保存 |
| 演示 Demo | 若干脚本的有序编排、章节说明与播放选项 | 业务仓库的演示配置，可由应用编辑 |
| 运行 Run | 一次演示的版本、步骤结果、失败原因与时间 | 本机运行记录；证据按需保存 |
| 转换报告 | 原测试与目标脚本的对应关系、改动、缺口和验证结果 | 业务仓库，与转换产物一起审阅 |

Playbook 的脚本库是对业务资产的登记和索引，不把客户脚本默认复制到产品源码仓库。应用自己的配置只保存工作区位置和界面偏好等信息。

## 主要使用流程

### 首次接入业务项目

1. 打开 Playbook，选择“添加项目”，定位业务工作区。
2. 应用发现脚本清单、环境配置和演示列表，显示脚本版本与环境名称。
3. 开发者通过转换 Skill 将某个 TC 转为脚本；应用首版支持刷新后发现结果。
4. 选择本地演示环境并完成登录或引用私有会话。显示真实服务、测试数据或 Mock 的实际类别。
5. 执行预检，检查目标地址、浏览器、所需角色、数据和脚本版本是否可用。

首版不做全功能代码编辑器。应用可编辑标题、章节、顺序、讲解与节奏；动作、断言和准备逻辑在业务代码中维护，由原编辑器或智能体修改。

### 组织与播放一场演示

1. 在“演示”中新建一场验收或培训演示，按顺序加入业务脚本，选定环境。
2. 设置开场介绍、章节衔接、默认阅读停留和光标移动速度，查看预计时长。
3. 点击播放，打开由 Playwright 管理的独立 Chrome 窗口。Playbook 窗口作为控制台，不向业务页面授予桌面权限。
4. 页面中央显示本章名称与目标。定位控件后显示箭头说明，叠加半透明灰色蒙层，光圈随演示光标移动。
5. 由原生 Playwright 逻辑执行点击、输入、滚动等操作；断言通过才进入下一步。
6. 结束页展示已完成流程与结果，支持从开场再播放。写入流程重播前必须按其声明恢复或重新准备数据。

鼠标光圈是演示层绘制的视觉光标；实际动作由 Playwright 执行。提示层不重复执行点击，不替换业务定位逻辑。读屏与视觉主题采用应用固定样式，不要求业务项目自己拼装 Driver.js。

### 暂停、失败与接管

- 暂停优先停止呈现、阅读计时和后续动作调度。已经发出的网络请求或单个 Playwright 调用不会被时间倒流；状态显示“正在暂停”，等动作到达安全边界后显示“已暂停”。
- 首版支持暂停后人工答疑；人工改变页面后，继续前重新检查当前步骤前置条件，无法确定则从流程入口重启。
- 目标消失、断言失败、登录过期或浏览器关闭时，停在具体步骤，显示失败原因和已完成项，不宣告演示成功。
- “停止”阻止后续步骤并释放本轮资源；对仍在执行的操作采用有界等待，必要时关闭本轮独立浏览器。不能把停止承诺为撤销已完成写入。
- 首版只提供整段重新播放，不提供任意步骤跳转、失败后盲目自动重试或对写入操作自动重复点击。

## 页面结构

| 页面 | 核心内容 | 主要操作 |
|---|---|---|
| 项目 | 工作区、环境、接入状态 | 添加目录、检查环境、打开目录 |
| 脚本 | 名称、来源 TC、步骤数、角色、数据类别、最近结果 | 查看步骤、预览讲解、试播、打开源文件 |
| 演示 | 章节与脚本顺序、环境、预计时长 | 新建、排序、保存、播放 |
| 播放控制台 | 当前章节、步骤、环境、进度与异常 | 暂停、继续、停止、从头再播 |
| 运行记录 | 时间、脚本版本、环境类别、结果、失败步骤 | 查看详情、定位源码、按需导出记录 |

“脚本”和“演示”分别管理业务流程和面向观众的编排。演示配置引用脚本，不复制动作代码。

## 脚本与测试复用

采用 TypeScript 原生脚本。每一步包含稳定 ID、标题、讲解、可选目标定位、原生 `run` 操作和 `verify` 断言。章节、提示方向、阅读时长是呈现元数据。

测试入口使用原业务 fixture 完成数据准备、权限与登录，然后调用共享流程，使用 `test.step` 产生测试报告；演示入口使用所选 Profile 准备上下文，再调用同一流程并添加呈现。演示速度不改变超时语义、预期结果或数据边界。

| 转换方向 | 首选交付 | 必须保留 | 不能自动假设 |
|---|---|---|---|
| TC → Script | 共享业务流程 + 保留原测试配置的 TC 入口 + 转换报告 | 动作顺序、断言、角色、前置数据、清理和 mock | 所有测试都适合客户展示；测试账号等于真实账号 |
| Script → TC | 引用共享流程的标准 TC；需要独立分发时展开为原生 TC | 原断言、准备、清理、等待事件和数据副作用 | 提示文案可自动变成业务断言；任意 TS 均可无损静态导出 |

转换由智能体按 Skill 处理。首版不内置模型服务，不承诺一键转换任意代码。未识别的 fixture、闭包、动态分支和自定义 matcher 要保留依赖或列为明确缺口，不能静默删除。

## 首版范围

| 能力 | 首版要求 |
|---|---|
| 桌面应用 | macOS 首发，安装应用后无需额外 Node 服务或终端操作 |
| 项目与脚本管理 | 登记业务工作区、发现脚本、查看步骤和来源、打开源文件 |
| 演示管理 | 组合脚本、调整顺序、章节与节奏，选择环境并保存 |
| 播放效果 | 中央开场、箭头 pop-up、灰色蒙层、光圈移动、点击反馈和自动操作 |
| 浏览器 | 首先支持本机 Chrome 的独立会话；检测安装情况，明确缺失原因 |
| 流程可靠性 | 真实结果检查、暂停继续、停止、从头重播、步骤级失败说明 |
| 环境与数据 | 区分 real / fixture / mock；脚本声明副作用、重播策略与角色 |
| 测试关联 | 流程与 TC 双向关联，提供共享与独立导出的示例和 Skill |
| 本地记录 | 保存版本、环境类别、结果与失败步骤，按需截图，默认不录制登录 |

## 技术决策

- Electron 提供桌面界面和随应用分发的 Node 运行环境，不另设常驻本地 HTTP 后端。播放器在独立运行进程中执行，避免长流程阻塞桌面窗口。
- React + TypeScript 构建管理界面；Playwright 保留浏览器控制、Locator、自动等待、多页等原有能力；Driver.js 负责元素引导，蒙层与光标等由产品呈现层补充。
- 浏览器演示优先采用独立 Chrome，而非把客户系统嵌入拥有桌面桥接能力的窗口。桌面应用的 Chromium 界面与被演示浏览器是两个用途不同的窗口。
- 首版使用文件作为业务资产真源，应用保存轻量本地索引，不引入云账号、同步后台、消息队列或数据库服务。
- Profile 把登录、准备与释放逻辑同流程分离，但保留业务仓库原有 fixture 生命周期，不在产品里重建一套测试框架。
- 脚本是有本机权限的受信任 TypeScript 代码。应用只运行用户明确接入的工作区，不自动执行网络下载脚本；进程分离不代表恶意代码安全沙箱。

## 用户故事

1. 作为交付人员，我希望选择项目和环境后直接播放，便于重复演示核心流程。
2. 作为观众，我希望先知道业务目标，再看到具体入口、说明、动作和结果，便于理解系统用途。
3. 作为培训人员，我希望暂停答疑后继续，在环境变化时得到明确提示，便于掌控讲解节奏。
4. 作为演示组织者，我希望组合多个脚本并调整章节顺序，便于适应不同验收和培训主题。
5. 作为开发者，我希望动作和断言只维护一次，便于业务改版时同时修复演示和测试。
6. 作为测试人员，我希望转换保留 fixture、断言和清理，便于信任测试结果。
7. 作为智能体，我希望有清楚的脚本契约、实例和缺口报告规范，便于生成可验证的转换产物。
8. 作为项目负责人，我希望知道演示连接的是真实环境还是模拟数据，便于准确判断演示结果的意义。

## 验证与验收

| 场景 | 通过条件 |
|---|---|
| 干净机器安装 | 用户安装应用并具备受支持 Chrome 后，无需安装 Node 或启动服务即可打开样例；开发依赖和业务 Profile 依赖检查有清楚结果 |
| 引导呈现 | 开场、箭头、蒙层、光标光圈和动作连续播放；页面滚动、SPA 更新和原生 dialog 下仍可见且不阻挡操作 |
| 动作正确 | 每步按原生 Playwright 语义执行，实际预期结果通过后进入下一步 |
| 暂停停止 | 暂停后不发起新动作；停止后不继续后续步骤；重播遵守数据恢复策略 |
| 失败路径 | 刻意隐藏控件或破坏预期状态时准确停下，保留失败步骤，不显示成功 |
| TC 双向复用 | 同一模拟用例的原 TC、共享流程 TC、独立导出 TC 在相同数据上结果一致；改变预期结果时三者均失败 |
| 业务试点 | 在艺工本地实际服务上串起一段只读流程，无意外业务写入；正式身份与现场环境另外核验 |
| 版本与记录 | 每轮记录脚本与依赖版本、运行环境类别；修改代码后旧结果仍标识原版本 |

契约/执行器测试检查动作、断言顺序和失败传播；浏览器测试检查真实 DOM 操作；桌面集成测试检查 IPC、运行进程、打包和异常退出；业务验收使用相应环境，不把合成页面通过当成业务集成通过。

## 分阶段交付

1. **契约与转换基础（本次）**：产品方案、TypeScript 契约、参考执行器、合成页面正反示例、Skill 及其验证。
2. **桌面最小闭环**：Electron 管理窗口、选择一个业务脚本与环境、独立 Chrome 播放、引导层、暂停停止、错误显示和 macOS 安装包。此阶段先验证“装好即可演示”。
3. **脚本与演示管理**：工作区索引、来源关联、步骤预览、讲解编辑、演示编排、运行记录、版本快照。
4. **试点与发布完善**：接入艺工脚本，验证真实本地业务、多轮重播和环境恢复；完成签名、公证、依赖锁定、更新与离线分发验证。

第二阶段应先做打包后的 Playwright 启动与 Driver.js 注入验证，再展开管理界面，及早发现 Electron 内置运行环境、浏览器路径与资源打包问题。

## 首版不包含

视频录制与剪辑、语音合成、浏览器扩展、全平台原生桌面自动化、云端远程控制、多人协作与账号体系、内置 AI 对话、任意 TS 无损转换、完整可视化动作编辑器、从任意步骤恢复、自动修复定位与对生产写入盲目重试。

首版面向网页系统演示。多标签页、跨域 frame、文件上传、下载、操作系统对话框等能力继续依赖 Playwright，但其演示呈现与打包兼容性须逐项纳入后续支持矩阵，不能仅凭底层 API 存在就宣称全部完成。
